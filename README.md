# Gemini Browser Skill Agent

실행 중 사용자가 URL과 작업을 계속 입력하면 페이지를 분석해 URL 전용 도구를 생성하고, 브라우저에서 실행한 뒤 루트 에이전트가 성공 여부를 검증하는 Python CLI입니다. 모든 LLM 호출과 대체 모델은 Gemini만 사용합니다.

## 실행

Python 3.11 이상이 필요합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium
# 기존 .env가 없을 때만 .env.example을 복사하고 키를 설정합니다.
python main.py 'https://tongnamuu.github.io/ToDoList/' '우유 사기 할 일을 추가해줘'
```

대상 URL은 환경변수를 사용하지 않고 매 요청으로 받습니다. 여러 사이트의 작업을 순서대로 실행할 수 있습니다.

```sh
python main.py --job 'https://example.com/todos' '우유 사기 추가' --job 'https://example.org/calendar' '오늘 일정 확인'
```

기본적으로 프로그램은 계속 실행됩니다. `python main.py`는 즉시 URL과 작업을 반복 입력받고, 시작 인자나 `--job`이 있으면 해당 작업을 처리한 뒤 다음 입력을 기다립니다. `/quit`로 종료하고 `/skills`로 누적된 URL·도구·버전을 확인합니다. 입력한 작업만 실행하고 종료하려면 `--once`를 사용합니다. 각 요청은 독립적으로 검증·재시도하며, 하나가 실패해도 다음 요청을 실행합니다. 같은 브라우저 세션과 스킬 레지스트리를 재사용하고 결과는 요청별로 저장합니다.

기존 `.env`의 `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY`를 사용합니다. 키는 프롬프트나 로그에 포함하지 않습니다. 실행 브라우저의 로그인 상태는 `.browser-profile/`에 유지됩니다. 프로필과 실행 기록에는 개인 정보가 포함될 수 있으므로 Git에서 제외합니다. 같은 프로필을 여러 프로세스에서 동시에 사용하지 마세요.

## 동작

1. 실제 브라우저 URL로 등록 스킬을 조회합니다. 스킬이 없으면 현재 화면의 컨트롤과 텍스트를 분석합니다.
2. Gemini가 이름·입력 파라미터·선언형 브라우저 단계로 구성된 도구들을 만듭니다. 생성 코드를 실행하지 않고 허용된 Playwright 동작만 실행합니다.
3. `skills_store/`에 URL별 JSON 패키지와 레지스트리 인덱스를 저장하고 즉시 활성화합니다. 이후 프로세스에서도 불러옵니다. 기존 URL에 부족한 기능이 있으면 추가하고 버전을 갱신합니다. 등록은 기존 기능을 보존하며 같은 이름의 도구만 갱신합니다. 파일은 임시 파일 작성 후 원자적으로 교체해 중간 쓰기로 인한 손상을 줄입니다.
4. 실행기는 해당 URL의 도구만 선택합니다. 매 단계 직전에 URL을 재검사합니다. 리다이렉트 시 실제 도착 URL로 다시 라우팅하며, 다른 URL의 도구를 이어 실행하지 않습니다.
5. 루트 검증기가 실행 전후 화면과 이력을 비교해 성공/실패 및 증거를 반환합니다. 실패하면 현재 상태와 오류를 바탕으로 스킬을 보수하고 한 번 더 실행합니다. 전체 실행 시도는 최대 2회, 시도당 판단 루프는 30회입니다.
6. 로그인·CAPTCHA는 사용자가 열린 브라우저에서 직접 완료하고 터미널에서 Enter를 누릅니다. 추가 정보가 필요하면 터미널로 질문하며 답변 후 이어갑니다. `/cancel`로 취소합니다.

URL은 스킴·호스트 대소문자와 기본 포트만 정규화합니다. 경로 대소문자, 마지막 슬래시, query 순서와 빈 값, 해시 라우트는 보존합니다. `/todo`, `/todo/`, `/todo#done`은 각각 다른 스킬입니다. HTTP(S)만 지원합니다.

실행 결과는 `status`, `attempts`, `reason`, `evidence`, `url`로 반환하고 전체 이벤트는 `runs/`에 JSON으로 저장합니다. CLI 종료 코드는 성공 0, 실패/취소 1입니다.

## Gemini 모델

| 역할 | 기본 모델 | 대체 모델 |
| --- | --- | --- |
| 루트 검증 | gemini-3.8-flash | gemini-3.6-flash |
| 페이지 분석·스킬 생성 | gemini-3.8-flash | gemini-3.6-flash |
| 도구 선택·실행 판단 | gemini-3.5-flash-lite | gemini-3.8-flash |

분석·검증에는 추론 성능을, 반복적인 도구 선택에는 비용과 응답 속도를 우선했습니다. 공식 모델 목록: https://ai.google.dev/gemini-api/docs/models
`GEMINI_ROOT_MODEL`, `GEMINI_SYNTHESIZER_MODEL`, `GEMINI_EXECUTOR_MODEL`로 프로젝트에서 사용 가능한 Gemini 모델을 지정할 수 있습니다. 404/429/500/503일 때만 Gemini 대체 모델을 시도하며 인증 오류는 그대로 반환합니다.

## 검증 및 범위

```sh
python -m unittest discover -s tests -v
```

테스트는 가짜 모델/브라우저를 사용해 URL 격리, 스킬 영속성, 재시도 상한, 입력 후 재개, 취소를 검증합니다. 실제 Gemini 응답 품질이나 웹사이트 제어 성공을 보장하는 통합 테스트는 아닙니다.

현재는 로컬 단일 사용자 CLI MVP입니다. iframe·새 탭·파일 업로드·캔버스 전용 UI는 지원하지 않습니다. 작업 도중 페이지 이동은 다음 판단에서 새 URL 스킬로 처리합니다. DOM 관찰 기반 성공 판정이며 서버 데이터의 최종 반영까지 자동 보장하지 않습니다. 재시도는 현재 상태를 보고 진행하도록 설계했으나 임의 사이트에서 중복 변경을 완전히 방지하는 트랜잭션 보장은 없습니다.

## 여러 사이트의 스킬 조합

루트 워크플로 에이전트는 전체 URL 스킬 목록에서 다음 작업에 필요한 사이트를 선택하고 사이트별 실행기에 위임합니다. 사이트별 실행기는 해당 URL 도구만 사용합니다. 매 단계의 검증 결과와 화면 관찰(제목·ID·링크 등)을 다음 단계에 전달합니다.

```sh
python main.py --task '블로그 글 작성이라는 할 일을 추가하고, 블로그에 글을 작성한 뒤, 해당 할 일을 완료 처리해줘' --site 'https://example.com/todos' --site 'https://example.org/editor'
```

이미 등록된 URL은 `--site` 없이 스킬 목록에서 선택할 수 있습니다. 켜 둔 프로그램에서는 `/task`를 입력해 여러 사이트를 조합하는 전체 작업을 요청합니다. 등록되지 않았고 입력으로도 주어지지 않은 URL은 루트가 임의로 추측해 실행하지 않으며 사용자에게 요청합니다.

루트는 다음 하위 작업을 매 단계 결정하므로 `Todo → Blog → Todo`처럼 같은 사이트로 돌아갈 수 있습니다. 한 단계라도 검증 실패하면 종속 후속 단계는 중단합니다. 모든 단계가 끝나면 전체 요구사항과 순서를 별도로 검증하고, 실패 시 성공한 변경 이력을 보존해 한 번의 보완 실행을 진행합니다. 사이트별 실행기의 실패 재시도도 최대 1회입니다.

CLI의 사이트별 실행기는 `site_agent.py`, 여러 사이트의 루트는 `workflow.py`에 있습니다. 워크플로 테스트는 가짜 모델·브라우저로 사이트 왕복 순서, 결과 전달, 실패 시 후속 단계 차단을 검증합니다. 실제 사이트에서의 의미상 작업 분해·대상 식별은 Gemini 판단에 의존하며, 실환경 통합 검증이 추가로 필요합니다.

## 웹 화면에서 스킬 선택과 워크플로우 구성

`app.py`의 웹 화면 상단에서 사이트별 스킬을 확인할 수 있습니다. 각 기능의 **+ 단계 추가**를 눌러 워크플로우에 넣고, 입력값을 채운 뒤 **위로 / 아래로** 버튼으로 순서를 정합니다. 동일한 사이트로 돌아가거나 같은 스킬을 여러 번 추가할 수 있습니다.

이름을 입력하고 **워크플로우 저장**을 누르면 `workflows_store/`에 저장됩니다. 저장 목록의 **불러오기**로 편집하고 **실행**으로 순서대로 실행·검증합니다. 저장 후 스킬 정의가 바뀌면 재저장을 요청하여 의도하지 않은 변경 실행을 방지합니다. 단계가 실패하면 후속 단계는 실행하지 않습니다. 로그인 요청은 브라우저에서 처리한 후 **로그인·입력 완료 후 재개**를 누릅니다. 재개 정보는 현재 서버 프로세스에서 유지되며 서버 재시작 후에는 새로 실행해야 합니다.

단계 입력값은 사용자가 직접 지정합니다. 예를 들어 할 일 추가와 완료 단계에는 같은 할 일 이름을 입력합니다. 이전 단계 결과를 자동으로 변수에 연결하는 편집 기능은 포함하지 않습니다.
